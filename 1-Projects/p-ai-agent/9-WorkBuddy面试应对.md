# WorkBuddy 售后面试应对指南（2026版）

## 岗位核心理解
用户用 AI 编程助手出问题 → 提交工单 → 你排查、解决或转研发 → 写文档复用

## 你的匹配度

### 强项
- 手写过 Agent 框架 → 懂 LLM/Tool Calling/RAG 原理 ✅
- Python + Docker + AWS 全链路实战经验 ✅
- 14 条 ERROR_LOG 踩坑记录 → 真实排查能力 ✅
- 文档沉淀意识（ERROR_LOG/DISASTER_RECOVERY） ✅

### 弱项（面试前准备好）
- 没有正式售后经验 → 用项目排查经验弥补
- 不了解 WorkBuddy → 面试前去了解产品
- 7x24 轮班 → 面试时确认排班制度

## 排查四步法（背下来）
1. 看日志（docker logs / 客户端日志）
2. 分层排查（网络/API Key/进程/配置）
3. 定位根因（curl/分段测试/对比正常情况）
4. 给出方案+写文档

## 面试核心话术

Q: 用户说 CodeBuddy 不回复了？
A: 确认表现 → 看日志 → 分层测API/网络/配置 → 定位根因

Q: 用户说回答质量变差？
A: 确认时间点 → 查模型版本/配置变更 → 看prompt和原始返回

Q: 之前修过的问题又出现了？
A: 说明根因没修彻底 → 对比两次现象 → 重新定位+加防复发方案

Q: 没有售后经验为什么能做？
A: 虽然没售后经验，但开发项目踩过14个坑，全自己定位解决，这就是售后的核心能力。

Q: 为什么不做开发做售后？
A: 售后离用户最近，能最快理解产品在实际场景的问题。

## 面试官最在意的三件事
1. 你真的懂 Agent 原理吗 → 手写过，不只是调 API
2. 你会排查问题吗 → 14条ERROR_LOG案例
3. 你能接受轮班吗 → 先确认排班制度，展现灵活态度
