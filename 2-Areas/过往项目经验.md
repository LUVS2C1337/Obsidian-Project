# 过往项目经验 — 售后工程师方向（STAR重构）

> 针对 WorkBuddy 售后工程师岗位，把你过去做的三个项目重新梳理，
> 侧重点从"实施交付"转到"问题排查+客户支持+文档沉淀"。

## 项目一：澳门银河 MySQL 迁移 OceanBase

### STAR

**Situation**
客户核心业务系统数据量千万级，MySQL 性能瓶颈导致查询延迟，需要迁移到 OceanBase 分布式平台。客户是海外企业，涉及 20+ 家客户，环境差异大、风险高。

**Task**
主导迁移实施，核心要求两条：数据零丢失、业务零中断。同时要确保迁移完成后客户能自己运维。

**Action**
- 用 Jira 拆解任务，协调客户 IT、内部产研、运维三方对齐进度——涉及三方协作，沟通成本很高，每周同步进度确保不脱节。
- 用向日葵和 Bomgar 远程接入客户服务器，完成仿真测试和实际上线。客户环境各不相同，每次迁移前都要先做兼容性检查。
- 写 SQL 脚本做数据一致性校验，迁移前后用 Python 跑性能对比分析——确保迁移后性能确实提升了，不只是"感觉快了"。
- 针对 SQL 语法差异和数据结构兼容性问题提前排查，把常见坑整理成《数据迁移标准操作手册》，后面团队做类似项目可以直接复用。

**Result**
20+ 家客户全部迁移完成，数据零丢失，业务无中断。操作手册被团队复用。

**面试价值**
- 展示跨团队协调能力（客户 IT + 产研 + 运维）
- 展示排查和文档沉淀习惯（提前排查风险、输出操作手册）
- 展示远程排查能力（向日葵/Bomgar 远程接入）

## 项目二：SaaS 系统 MySQL 数据库拆分迁移

### STAR

**Situation**
客户 Oracle 单体数据库负载过高，业务频繁出现延迟。10 家企业客户需要做水平拆分和架构升级，涉及数据迁移和系统改造，割接风险高。

**Task**
负责 10 家客户的数据拆分落地，核心目标是控制割接风险、上线后系统稳定。

**Action**
- 用 Jira 拆解任务并跟踪进度，用 Python 写脚本自动化生成迁移校验报告——这样每次迁移的验收标准是统一的，不会漏检。
- 远程登录客户 Windows 服务器完成环境配置和脚本部署，用 Zoho Desk 跟踪工单，割接过程中实时监控状态。
- 把迁移过程中遇到的问题和解决方案整理成《SaaS系统数据库拆分实施指南》，规范后续类似项目的交付流程。

**Result**
10 家客户全部上线稳定。实施指南成为后续项目的标准参考。

**面试价值**
- 展示 Python 脚本能力（自动化校验报告）
- 展示 Windows 服务器运维经验（远程环境配置、脚本部署）
- 展示文档沉淀习惯（输出实施指南）

## 项目三：酒店数字化 SaaS 系统试点部署

### STAR

**Situation**
公司新一代 SaaS POS+TMS 一体化系统需要在海外标杆客户（澳门银河 Capella 酒店）完成试点部署，验证产品稳定性。这是公司的标杆项目，出问题影响很大。

**Task**
统筹试点全周期交付，确保准时上线，快速赋能客户团队。

**Action**
- 用 Teams 和海外客户周会同步进展，用 Zoho Desk 管理工单，问题全程跟踪闭环——客户在海外，沟通成本高，保持固定节奏的同步很重要。
- 到现场梳理餐饮、收银、库存等业务流程，设计分层培训体系（管理层、操作员、IT 运维），3 天内完成客户团队培训。
- 收集用户的反馈，转化成产品优化需求，推动交互体验和后台调度逻辑迭代。

**Result**
系统按时上线，成为公司标杆案例。客户反馈直接推动了产品改进。

**面试价值**
- 展示客户沟通和培训能力
- 展示问题收集→推动产品改进的闭环
- 展示标杆项目的交付经验
